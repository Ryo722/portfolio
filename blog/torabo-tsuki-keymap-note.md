# torabo-tsuki LP XSのキーマップを育てている話

## ケースの次はキーマップ

前回の記事でケースを自作した話を書いた。ハードウェア側が落ち着いたので、次はソフトウェア側 — キーマップのカスタムに取り組んでいる。

torabo-tsuki LP XSはZMKファームウェアで動作する。キーマップは設定ファイル（.keymap）を編集してGitHubにpushすると、GitHub Actionsでファームウェアがビルドされる。ビルドされたファイルをキーボードに書き込めば反映される仕組みだ。

現時点で14回のチューニングを重ねた。まだ完成とは言えないが、日常使いで困らないところまでは来た。

## 4レイヤー構成

現在のキーマップは4レイヤーで構成している。

- レイヤー0（ベース）: QWERTY配列。普段のタイピングはここ
- レイヤー1: 数字（1-0）、括弧類、トラックボールのクリック操作
- レイヤー2: 記号（!@#$%など）、ファンクションキー（F1-F12）
- レイヤー3（システム）: カーソル移動、ページ操作、Bluetooth切り替え

レイヤーの切り替えは親指キーの長押しで行う。lt 1 TABはタップでTab、長押しでレイヤー1に切り替わる。lt 3 RETはタップでEnter、長押しでレイヤー3。親指は常にこのキーの上にあるので、レイヤー移動のために指を動かす必要がない。

## hold-tapの調整 — 一番効いたチューニング

14回のチューニングの中で、最も使い心地を変えたのがhold-tapタイミングの調整だった。

### 問題

ZMKにはhold-tapという仕組みがある。1つのキーに「短く押したとき（タップ）」と「長く押したとき（ホールド）」で別々の機能を割り当てられる。例えば、Aキーをタップすればaが入力され、長押しすれば左Commandとして機能する。自作キーボード界隈ではこのテクニックをホームロウモッド（home row mods）と呼ぶ。修飾キーのために指をホームポジションから動かさなくて済む。

ただ、デフォルトの設定では2つの問題があった。

1. タップのつもりがホールド判定になる — 少しキーを押す時間が長いだけで、文字入力ではなく修飾キーとして認識される
2. 高速入力時の誤反応 — 修飾キーが割り当てられたキーを他のキーと素早く続けて打つと、意図しない修飾キー入力になる

### 解決

自分のタイピング速度をもとに、ChatGPTと相談しながらパラメータを決めた。

hmt: home_mod_tap {
    compatible = "zmk,behavior-hold-tap";
    flavor = "balanced";
    tapping-term-ms = <280>;
    quick-tap-ms = <175>;
    require-prior-idle-ms = <150>;
};

- tapping-term-ms = 280: タップとホールドの境界を280msに設定。デフォルトより長めにすることで、普通の入力速度でタップが誤ってホールド判定されるのを防ぐ
- quick-tap-ms = 175: 175ms以内に同じキーを再度押した場合、常にタップ扱いにする。連続入力時の誤爆防止
- require-prior-idle-ms = 150: 直前のキー入力から150ms以上経っていないとホールド判定を開始しない。高速タイピング中の誤反応を抑える

この3つのパラメータを導入してから、誤爆がほぼなくなった。14回のチューニングの中で一番大きなターニングポイントだった。

## コンボ — HHKBの手癖を引き継ぐ

HHKBからの移行で意識したのは、なるべく近い指の位置でキー入力できるようにすることだった。コンボはその手段の一つだ。

コンボとは、2つのキーを同時に押すと別のキーが発動する仕組み。現在3つ設定している。

- 言語切り替え: 左手小指付近の2キー同時押しでGlobeキー（macOSの入力ソース切り替え）
- シングルクォート: 隣り合う2キーの同時押しで ' を入力
- バックスラッシュ: 隣り合う2キーの同時押しで \ を入力

シングルクォートとバックスラッシュは、通常のキー配列では指を遠くまで伸ばす必要がある。コンボにすることでホームポジション付近で完結する。

## トラックボールの速度調整

torabo-tsuki LP XSのトラックボールはデフォルトだと少し遅いと感じた。移動速度を1.5倍に変更して、マウスカーソルの追従感を改善した。トラックボールのクリック操作はレイヤー1と3に割り当てていて、左クリック・右クリック・中クリックすべてキーマップ内で完結する。マウスに手を伸ばす場面はゼロになった。

## まだ育てている途中

キーマップに「完成」はないと思っている。使い方が変われば最適な配置も変わる。今後やりたいことをいくつか挙げておく。

- レイヤー2（記号）の配置見直し。プログラミングで頻出する記号をもっと打ちやすい位置に持っていきたい
- コンボの追加。使用頻度の高いショートカットをコンボ化する余地がある
- 条件付きレイヤー（conditional layers）の検討。特定のレイヤーの組み合わせで自動的に別レイヤーに遷移する仕組み

キーマップのチューニングはケース設計と違って物理的なコストがかからない。思いついたら試して、合わなければ戻す。この気軽さが楽しい。
