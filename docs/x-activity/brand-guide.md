## トーン

### DO
- 具体的な数値で語る（「テスト1,065件」「152モジュール」）
- 作業中のリアルな気づきを書く
- 技術選定の理由を短く添える
- AIとの協業を自然に含める（誇張しない）
- 「〜した」「〜にした」の事実ベース

### DON'T
- 自慢・マウント（「こんなの簡単」「みんな知らないけど」）
- 煽り・炎上狙い
- 宣伝臭の強い誘導（「詳しくはプロフィールのリンクから！」の連発）
- 技術用語の過剰な羅列（ツイート1本に技術名5個以上は多すぎ）
- 他者の批判・比較

## 投稿テンプレート

### 開発ログ
```
[何をしたか] + [具体的な成果] + [技術的なポイント1つ]

例:
ポートフォリオにブログビューア実装した。
react-markdown + remark-gfm を遅延ロードして
メインバンドルへの影響ゼロに抑えた。
```

### 技術メモ
```
[問題] → [原因] → [解決策]

例:
torch.load()がPyTorch 2.6+で壊れる問題、
weights_only=Falseのフォールバックで解決。
fairseq/hubertモデルの読み込みに必要。
```

### AI活用
```
[AIとの作業内容] + [人間がやったこと/AIがやったこと]

例:
Claude Codeに26プロジェクトを並列調査させて
5分でスコアリング完了。
人間は「載せる/載せない」の判断だけに集中できた。
```

### リリース告知
```
[何を公開したか] + [1行の説明] + [リンク]

例:
ブログ記事書いた:
「11,000枚のカードを動かすゲームエンジンをAIと書いた話」
ryo722.github.io/portfolio/
```
