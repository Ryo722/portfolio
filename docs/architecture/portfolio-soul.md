# Portfolio Soul — Ryo722 の「中の人」定義

## 1. このドキュメントの位置づけ

- `brand-book.md` の上位概念。ブランドブックが「どう見せるか」なら、このドキュメントは「誰が・なぜ作っているか」を定義する
- 全スキル（blog-writer, content-manager, brand-guard 等）が参照する基盤
- サイト全体のテキスト・トーンの最終判断基準

## 2. オーナーのポートレート

### 原点

ゲーム（ポケモン）が好きで、自分でも楽しいゲームを作りたいと思ったのがきっかけ。最初にコードを書いた時「これから自分もゲームを作っていけるんだ」とワクワクした。

### 原動力

自分か誰かが欲しいと思ったものが形になること。アイデアが見える形になることが楽しい。

### 人物像

毎日やりたいことがコロコロ変わる好奇心の塊。まず作ってみて学ぶタイプ。インプットが苦手（ブレインフォグ、思考が連想していく癖）。「ちょっとした好奇心があるだけの凡人」（本人談）。

### 正直な現実

- ほとんどのプロジェクトは自己満足と見栄
- 技術力はAIに支えられている
- 作って飽きたものもある
- DuelMastersPlaysだけは本当に人に届けたかった唯一のプロジェクト

### 信念

良いプロダクトとは「作り手のことが想像できて、参考にしたものへのリスペクトと愛が感じられるもの」。

## 3. サイト全体のトーン定義

| 軸 | 方向性 |
|---|---|
| 正直さ | 等身大で書く。できないこと・足りないことを隠さない |
| 好奇心 | 「作りたいから作った」という動機を自然に伝える |
| 敬意 | 参考にしたもの・助けてくれたもの（AIを含む）へのリスペクトを示す |
| 自負 | 凡人だけど10個のプロダクトを形にした事実は卑下しない |
| 温度 | 技術書ではなく、作り手の日記に近い温度感 |

## 4. 文章の Do / Don't

| DO | DON'T |
|---|---|
| 「作りたかったから作った」と書く | 「課題解決のために〜」と就活テンプレで書く |
| 「AIに助けてもらいながら」と正直に書く | AIの存在を隠す / AIに全部やらせた印象を与える |
| 「飽きたものもある」と認める | すべてのプロジェクトに壮大な意義を後付けする |
| 具体的な数字で事実を示す | 「多くの」「高品質な」等の曖昧な形容 |
| 「凡人だけど形にした」と書く | 「凡人です」で終わる（事実とセットにする） |
| 一文60字以内を目安にする | 修飾語を重ねた長文 |
| 「〜が楽しい」「〜にワクワクした」等の素直な感情 | 「passion」「revolutionize」等の大げさな表現 |
| 「フルスタック」と書くなら実際に構築した層を明示 | 根拠なく「フルスタック」を自称 |

### 禁止表現（就活テンプレ）

- 「イノベーションを推進」
- 「ソリューションを提供」
- 「シナジーを生む」
- 「プロアクティブに」
- 「パッションを持って」
- 「〜に貢献したい」（具体性なし）
- 「幅広い経験を活かし」

## 5. プロジェクト記事で盛り込むべき要素

1. **なぜ作ったか**（個人的な動機。「必要だったから」「面白そうだったから」レベルでOK）
2. **何を作ったか**（ユーザー視点で1行）
3. **どう作ったか**（技術選定の理由、設計判断）
4. **正直な振り返り**（うまくいったこと・いかなかったこと・飽きたなら飽きたと書く）
5. **数字**（テスト数、コミット数、ユーザー数など事実ベース）

## 6. セクション別ガイドライン

### Hero / Tagline
- 技術名で始めない
- 「何者か」ではなく「何を大切にしているか」が伝わる一行
- 好奇心・正直さ・ものづくりへの姿勢が滲む表現

### About
- 4段落構成: 原点 → 正直な現状 → それでも形にした事実 → これからの話
- \n\n 区切り
- 就活用の完璧な自己紹介にしない

### Projects
- 個別プロジェクトの説明文は本ドキュメントでは変更しない
- brand-book.md の表現ルールに従う

### Contact
- 「一緒に新しいことを形にしたい」という姿勢を反映
- 敷居を下げる表現にする
