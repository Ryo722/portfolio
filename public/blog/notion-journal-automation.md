# ChatGPT音声入力 → Notion自動追記の半自動ジャーナルを作った

## 何を作ったか

毎日の振り返りをNotionのDaily Journalに書いているが、PCの前に座ってキーボードで入力するのが面倒だった。

そこで、スマホのChatGPTアプリに音声で話しかけ、整理されたMarkdownをクリップボード経由でNotionに自動追記する仕組みを作った。

```
スマホで音声入力（ChatGPT）
  ↓
Markdownに整理
  ↓
クリップボードにコピー
  ↓
ターミナルでコマンド1つ
  ↓
Notion Daily Journal に追記
```

「完全自動」ではなく「半自動」にしているのは意図的だ。音声入力の整理はChatGPTに任せるが、Notionへの追記は人間がコマンドを叩く。内容を確認してから追記したいからだ。

## 3層スクリプト設計

シェルスクリプトを3つのレイヤーに分離した。

| レイヤー | ファイル | 責務 |
|---|---|---|
| プレゼンテーション | journal_push_clipboard.sh | クリップボードからテキスト取得 |
| ロジック | journal_push.sh | 時刻見出し付与、日付確定 |
| アダプター | notion_journal_adapter.sh | Notion API（ncli）操作 |

**プレゼンテーション層**。`pbpaste` でクリップボードの内容を取得し、ロジック層に渡すだけ。21行。

**ロジック層**。テキストの先頭が `## HH:MM` 形式でなければ、現在時刻の見出しを自動付与する。日付を確定し、アダプター層を呼び出す。132行。

**アダプター層**。Notion CLI（ncli）の操作を抽象化する。ページの検索、作成、コンテンツの取得・更新を関数化している。197行。

この分離により、「クリップボード以外の入力源に変更する」「ncli以外のNotionクライアントに変更する」といった変更が、1レイヤーの修正で済む。

## ncli による Notion API 操作

Notion公式APIを直接叩くのではなく、ncli（Notion CLI）を使っている。シェルスクリプトとの相性が良く、JSONの解析は jq で行う。

アダプター層の主な操作は以下の通り。

**ページ検索**。今日の日付のページがあるか検索する。なければ新規作成。同日内のページ検索結果はキャッシュして、APIの呼び出し回数を減らしている。

**追記の仕組み**。Notion APIには「末尾に追記」するエンドポイントがない。そこで、既存コンテンツを取得→新しいテキストを結合→全体を置換、という方法で追記を実現している。

**キャッシュ戦略**。`~/.cache/journal/` にページIDをキャッシュ。同日内は2回目以降の検索をスキップする。Notion APIは3 req/sec のレートリミットがあるため、キャッシュによる呼び出し削減は実用上重要だ。

## 日常の使い方

朝のルーティンは以下の通り。

1. スマホのChatGPTアプリを開く
2. 「今日やることを整理して」と音声入力
3. ChatGPTが箇条書きMarkdownで返す
4. 全文をコピー
5. Macのターミナルで `journal_push_clipboard.sh` を実行
6. Notionに追記完了

夜の振り返りも同様。「今日やったことを話す」→ ChatGPTが整理 → コマンド1つでNotionに追記。

## 振り返り

合計350行のシェルスクリプトで、日記の自動化ができた。

**「半自動」が正解だった**。完全自動だと、意図しない内容がNotionに書き込まれるリスクがある。人間がコマンドを叩くワンステップを残すことで、内容の確認とタイミングの制御ができる。

**シェルスクリプトでも設計は重要**。3層分離にしたおかげで、ncli のアップデートでAPIの挙動が変わったとき、アダプター層だけ修正すれば済んだ。レイヤー分離はどの言語でも効く設計パターンだ。

**音声入力 × LLM の威力**。キーボードで打つと5分かかる日記が、音声入力なら1分で話せる。それをLLMが構造化してくれる。入力のハードルが下がると、継続率が劇的に上がる。
