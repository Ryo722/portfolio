# blog-planner

ブログ記事の企画・ブリーフを作成する。

## トリガー
- `/plan-blog` コマンド実行時
- `blog-writer` からブリーフ不足時に呼び出し

## 入力
- $ARGUMENTS: テーマのキーワードまたはプロジェクト名

## 実行手順

### Step 1: テーマ調査
1. 指定されたテーマに関連するローカルプロジェクトを調査
2. README.md, CLAUDE.md, git log, ソースコードから技術的ポイントを抽出
3. 「何が面白いか」「何が独自か」を特定

### Step 2: 読者ペルソナ確認
以下の3ペルソナのうち、主対象を1つ選ぶ:

| ペルソナ | 特徴 | 求める情報 |
|---|---|---|
| 同業エンジニア | 同等以上のスキル | 設計判断、トレードオフ、ハマりどころ |
| 学習中エンジニア | 技術に興味あり | 全体像、使った技術の選定理由、再現手順 |
| 非エンジニア | 技術者を評価する立場 | 何を作ったか、規模感、ビジネス価値 |

### Step 3: ブリーフ作成

```markdown
# ブログ記事ブリーフ

## テーマ
[1行]

## 主対象ペルソナ
[上記3つから1つ]

## タイトル案（3案）
1. ...
2. ...
3. ...

## キーメッセージ
[この記事で最も伝えたい1文]

## 構成案
### H2-1: [見出し]
- ポイント

### H2-2: [見出し]
- ポイント

### H2-3: [見出し]
- ポイント

## 含めるべき具体データ
- [数値、コード例、スクリーンショット等]

## 想定文量
[短 / 標準 / 長]

## 関連プロジェクト
- [ポートフォリオ内のslug]
```

### Step 4: 人間確認
ブリーフを提示し、方向性の承認を得てから `blog-writer` に渡す。
