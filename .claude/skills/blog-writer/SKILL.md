# blog-writer

技術ブログ記事を企画・執筆する。`blog-voice` スキルのトーンを常時適用する。

## トリガー
- `/write-blog` コマンド実行時
- エージェント `blog-editor` からの委任時

## 入力
- $ARGUMENTS: テーマまたは記事ブリーフ

## 執筆手順

### Step 1: ブリーフ確認
1. テーマ・対象読者・キーワードを確認
2. ブリーフがなければ `blog-planner` スキルで作成

### Step 2: 構成設計
1. タイトル（日英）— 興味を引く、具体的な数値を含む
2. リード文（3行以内）— 何が書いてあるか・誰向けか
3. 見出し構成（H2 × 3-6セクション）
4. 各セクションの要点メモ

### Step 3: 執筆
以下の順序で段階的に書く:

1. **冒頭**: 課題提示 or 成果の提示（「〜を作った」「〜に困っていた」）
2. **背景**: なぜ作ったか / なぜこの技術か（動機 → 選定理由）
3. **本題**: 技術的な中身（設計判断、実装のポイント、つまずいた点）
4. **成果**: 数値で示す（テスト数、パフォーマンス、規模）
5. **振り返り**: 学んだこと / 次にやりたいこと

### Step 4: 品質チェック
1. `blog-voice` のトーンに合っているか自己チェック
2. `brand-guard` スキルでブランド整合性チェック
3. 技術的正確性の確認（コード例があれば動作確認）

## 出力形式

```markdown
---
title:
  ja: "日本語タイトル"
  en: "English Title"
date: YYYY-MM-DD
tags: [tag1, tag2]
excerpt:
  ja: "概要"
  en: "Excerpt"
---

本文（Markdown）
```

## 文量目安
- 短記事: 1,500-2,500字
- 標準記事: 3,000-5,000字
- 長記事: 5,000-8,000字

## 常時適用
- `blog-voice` スキル（トーン・文体）
- `brand-guard` スキル（ブランド整合性）
- `docs/architecture/portfolio-soul.md`（作り手の人間性定義）
