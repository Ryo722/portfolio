# blog-reviewer

ブログ記事の品質をレビューする。5軸で評価し、修正指摘を出す。

## トリガー
- `blog-editor` エージェントから委任時
- `/review-blog` コマンド実行時

## 入力
- 記事本文（Markdown）

## レビュー基準（5軸）

### 1. 構造（Structure）
- [ ] タイトルが具体的で興味を引く
- [ ] リード文が3行以内で内容を予告している
- [ ] H2見出しが論理的な流れになっている
- [ ] 各セクションが適切な長さ（長すぎない）
- [ ] 結論・まとめがある

### 2. 技術的正確性（Accuracy）
- [ ] 技術用語が正しく使われている
- [ ] コード例が動作する（または擬似コードと明示）
- [ ] 数値に根拠がある
- [ ] フレームワーク名・バージョンが正確

### 3. 読みやすさ（Readability）
- [ ] 一文60字以内が概ね守られている
- [ ] 段落が3-5文で区切られている
- [ ] 専門用語に必要な説明がある
- [ ] 冗長な表現がない

### 4. トーン適合（Tone）
- [ ] `blog-voice` のDO/DON'Tに準拠
- [ ] チュートリアル口調になっていない
- [ ] 過度な装飾・自虐がない
- [ ] 「AIとの共同開発」の文脈が自然

### 5. SEO・発見性（Discoverability）
- [ ] タイトルにキーワードが含まれている
- [ ] メタディスクリプション（excerpt）が魅力的
- [ ] タグが適切（3-5個）
- [ ] 内部リンク（関連プロジェクト）がある

## 判定

| 評価 | 基準 |
|---|---|
| PASS | 全軸で重大指摘なし |
| REVISE | 軽微な修正1-3件（修正後に再レビュー不要） |
| REWORK | 構造的な問題あり（修正後に再レビュー必要、最大2回） |

## 出力形式

```
## Blog Review

| 軸 | 評価 | 指摘 |
|---|---|---|
| 構造 | PASS/REVISE/REWORK | ... |
| 正確性 | PASS/REVISE/REWORK | ... |
| 読みやすさ | PASS/REVISE/REWORK | ... |
| トーン | PASS/REVISE/REWORK | ... |
| SEO | PASS/REVISE/REWORK | ... |

総合判定: PASS / REVISE / REWORK

### 修正指摘
1. [優先度: 高/中/低] 指摘内容
2. ...
```
